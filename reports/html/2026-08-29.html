#1 capcut-cli v0.21 可迁移草稿门禁：嵌套时间线修复 → 素材内置 → 隐私检查 → 再交付 · 99

核心判断：v0.21.0 把 CapCut Mac 9.2.8 已有人手验证的 Timelines/<id>/ 修复做成显式 opt-in，并新增 relink --stage 将重连素材复制进草稿 assets、fixture --check 检查 home path/邮箱/device id 等隐私残留，同时让每次写拒绝明确标出 editor-open、version-boundary、draft-changed-on-disk、mirror-newer 等门禁。价值不是功能更多，而是把“这份草稿能不能安全交给别人/换机器打开”变成可验证流程。

解决的问题：解决批量生成或修复后的剪映草稿在另一台机器黑屏、嵌套时间线写了却不生效、调试包泄露本机信息，以及写入失败时无法判断到底是哪条保护规则拦截的问题。

主流方案对比：直接复制整个草稿目录最快，但外部绝对路径、版本布局和隐私残留都不可控；完全手工重连可靠但成本高。v0.21 的做法是只对已确认问题启用修复，再把相关媒体 stage 进草稿，并用机械检查收尾，适合自动化后的人类交付。

今天可以做：复制 1 个真实测试草稿：先 version/diagnose；若确认是 nested Timelines 布局再跑 sync-timelines --nested；对 2–3 个外部素材用 relink --stage；最后 fixture --check，并在另一份目录用剪映实际打开，核对素材、字幕、时长与首尾帧。

后续机会：若 3 个不同草稿都能跨目录/跨机器保持可打开，再把“stage + privacy check + open test”固定成批量草稿交付门禁；否则只保留 diagnose，不自动修复。

#2 ClipForge 镜头验收账本：每镜头保留候选 → 证据评分 → 人工采用 → OTIO/EDL 回专业剪辑 · 98

核心判断：8 月 28 日新增 shot quality gate：每个生成 take 都保留，按画面、时序、脚本遵循、主体身份、动作绑定、连续性和文字给出可核对证据，只有人工接受的候选进入真实合成；项目同时已有最长约 2 小时的可续跑本地转录编辑，并可导出 OTIO/EDL/CSV。真正的机会是把 AI 当候选生成和粗剪层，而不是让它覆盖素材或直接决定最终片。

解决的问题：解决 AI 生成镜头反复覆盖、无法追溯为什么选这一版，以及长素材文字粗剪完成后被困在独立工具里、无法回 DaVinci 精剪的问题。

主流方案对比：纯一键成片省操作但把失败镜头和模型选择藏在黑盒；手工逐条下载比较又很慢。保留全部 take + 人工 acceptance + OTIO/EDL 交接，牺牲一点自动化速度，换来可回退和可进入专业 NLE 的资产。

今天可以做：只拿一个 30–60 秒真实素材或一个 3 镜头生成任务测试：每镜头最多 3 个候选，不允许自动重花钱；人工只接受明确愿意入片的版本；粗剪后导出 OTIO/EDL，回 DaVinci 检查切点和素材引用是否一致。

后续机会：如果连续 3 次测试都能把“候选选择理由 + 最终采用版本 + NLE 交接”留痕，再考虑把现有 AI_analysis / Shot Mapping 也改成同类验收账本；否则只借鉴方法，不迁移工具。

#3 小红书发布确认链：草稿评估 → 显式 confirm 才发布 → 一键复制人工发布兜底 · 96

核心判断：8 月 28 日把 /publish <id> [confirm] 和 /copy <id> 放到免费模式主界面，但保持原有语义：发布必须显式 confirm，degraded mode 会阻断发布，/copy 只复制草稿用于人工发布。价值不是“自动发布更方便”，而是把研究/创作与账号写操作清楚分层，并始终保留无账号自动化风险的人工兜底。

解决的问题：解决内容草稿完成后流程断裂，以及 Agent 在用户没明确批准时直接触发平台发布的权限风险；同时保留账号状态异常时的手动发布路径。

主流方案对比：全自动发布节省最后几分钟，但账号风控和误发成本高；完全手工则无法利用前面的内容分析。显式 confirm + copy fallback 是更适合真实运营的中间态：AI 做到“可发”，人决定“现在发不发”。

今天可以做：只用 1 条已完成草稿测试完整生命周期：先 evaluate，再执行 copy 走人工发布，不启用自动发布；记录从草稿确认到真正发出的额外步骤。只有确认自动发布能显著省时间且账号状态稳定，下一轮才测试 confirm。

后续机会：若人工发布仍是主要路径，就只保留 draft/evaluate/copy；若 confirm 发布连续多次稳定，再把发布后 engagement snapshot 与原草稿 anchors 对照，形成栏目级复盘，而不是扩大自动发布权限。

#4 OpenBiliClaw 时效分层：迭代型内容 60 天衰减 → 过期候选先淘汰 → 再让模型评估 · 95
