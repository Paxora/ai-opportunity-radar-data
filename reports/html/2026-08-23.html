#2 Resolve 高风险写入最终画面验收 · 98

核心判断：近期连续修复 Fusion keyframe、source range、控制面板和写保护问题说明：Resolve 自动化最危险的不是缺工具，而是 API 返回成功却没有得到预期结果。高风险视觉修改必须以最终合成帧为最高级验收。

解决的问题：避免 Fusion、Title、grade、关键帧等操作出现参数可读回、结构也存在，但实际画面不对或根本没变化的假成功。

#3 capcut-cli 草稿兼容门禁 · 96

核心判断：当前最有价值的不是继续增加剪映效果，而是把版本、草稿布局、素材存在性、字幕和 timeline drift 在打开剪映之前检查清楚。项目已经把 lint、version guard、info-primary 布局和 sync-timelines 做成确定性门禁。

解决的问题：减少 AI 批量写草稿后才发现版本不兼容、镜像 timeline 未同步、素材丢失或字幕结构异常，导致整批草稿返工。

主流方案对比：直接改 draft JSON 成本最低但容易静默失败；完整 API 服务更重。CLI 门禁适合保留可编辑草稿，同时在写入前后做确定性检查。

今天可以做：拿一个现有测试草稿只跑 version/diagnose/lint，不先修改内容；确认当前 Mac 草稿布局、版本边界和素材引用全部通过后，再做一次最小字幕或片段修改并重新 lint。

后续机会：把 diagnose + lint 固定成任何 AI 草稿生成后的验收步骤；只有失败类型连续出现且 CLI 无法修复时，再考虑更重的 CapCut API/MCP。

#4 OpenBiliClaw 本地反馈画像 · 94

核心判断：其 Agent bridge 已把 recommend、submit-feedback、save-local、list-saved 与显式 allow-state-changing 的外部同步分开。价值是先在本地积累真实喜欢/不感兴趣和收藏证据，而不是让推荐系统直接改外部账号。

解决的问题：解决跨平台案例研究时反馈散落、无法沉淀，同时避免自动化为了同步收藏或状态而拥有过大的外部写权限。

主流方案对比：普通收藏夹只能保存内容，普通推荐器又常把隐式行为直接当偏好；本地显式反馈更慢，但可解释、可回滚，也更适合训练长期选题画像。

今天可以做：只用本地 recommend + feedback + save-local，选10条候选并明确标记喜欢/不感兴趣及一句原因；不要开启 sync-saved 外部状态写入。

后续机会：连续一周统计哪些反馈维度真的能提高可拍选题率；只保留有效维度，再决定是否接入更多平台来源。
