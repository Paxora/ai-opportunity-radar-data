#1 Resolve 统一操作验收：Agent 写入 → _operation 状态/变更/验证证据 → 只接受真实成功的剪辑结果 · 99

核心判断：新的标准 _operation envelope 把 success / partial / blocked / failed、verification、changes、warnings 统一到复合工具结果里。真正价值是让上层 Agent 不再逐工具猜“有没有真的改成功”。

解决的问题：API 没报错、局部成功或未验证却被当成完整成功，错误时间线继续流向后续步骤。

主流方案对比：逐工具写判断最快但维护成本高；只看异常又识别不了 partial 和 unverified。统一状态封装更适合作为全链路门禁。

今天可以做：在测试项目跑一个读取、一个确定性写入、一个可能被阻断的写入，检查 _operation.status、verification、changes、warnings 是否足够稳定。

后续机会：10 次真实写入都能可靠分类后，把它设为 Blueprint → Shot Mapping → Timeline 的统一确认门；unverified 或 partial 默认人工复核。

#2 B站字幕优先案例蒸馏：候选视频 → 原生字幕轨 → Hook/结构/金句证据卡 → 只对高价值样本下载画面 · 98

核心判断：OpenBiliClaw v0.3.216 已把可用字幕轨并入 play-url 响应。内容研究时先读字幕做结构筛选，再只下载真正值得研究的视频，明显低于全量下载 + ASR 的前置成本。

解决的问题：为了判断一个视频值不值得研究，就先下载完整视频、抽音频和转录，筛选成本过高。

主流方案对比：Whisper 全量转录最通用但筛选阶段成本高；标题/简介又缺正文证据。原生字幕更适合作为第一层淘汰证据。

今天可以做：选 10 条候选，只读取字幕轨，输出前 15 秒 Hook、3 段结构、1 个可复刻动作和淘汰理由；只下载最终保留的 2 条做关键帧复核。

后续机会：若无需下载就能稳定淘汰 70% 以上低价值样本，就固定“字幕先筛 → 画面后验”；无字幕再回退 ASR。

#3 M1 Max 本地补镜头试验：真实 2–5 秒缺口 → FastH3/MLX 三候选 → 只按入片率决定是否继续 · 96

核心判断：FastH3 已可通过 MLX 在 Apple Silicon 本地运行。最值得验证的不是搭新平台，而是让现有 Mac 直接承担低成本缺镜头草图层，先证明镜头值得生成。

解决的问题：每次验证补镜头想法都依赖云模型、上传素材并产生费用，试错门槛过高。

主流方案对比：云端旗舰模型质量通常更高；完整 ComfyUI 控制强但配置复杂。FastH3/MLX 更适合先做本地候选，入选后再升级。

今天可以做：只选 1 个真实缺口，按官方 Apple Silicon 路径跑通 FastH3，最多生成 3 条，记录耗时、内存峰值、主体一致性和是否愿意入片。

后续机会：若本地结果能承担草图筛选，就只把入选镜头升级云端；速度或质量不达标立即停止，不继续工程化。

#4 小红书长期偏好审核：改稿反馈 → learning signal → 周期性人工批准 → 才更新 Creator Model · 95

#5 剪映 Agent 最小权限：Wasm 只做时间线规划 → schema 校验 → CLI 写草稿 → lint/人工实开 · 92

核心判断：capcut-cli 没有新的功能提交，因此不制造新版本叙事。当前最值得保留的是让 LLM 只在沙箱里规划，真实文件写入继续走确定性 CLI。

解决的问题：Agent 拿 shell/文件系统权限后，一个错误决策就可能损坏草稿、素材路径或其他本地文件。

主流方案对比：Agent 直写步骤少但风险高；固定脚本最稳但不灵活。沙箱规划 + CLI 受控写入是成本与安全性的中间层。

今天可以做：验证 1 个 20–30 秒草稿：Wasm 输出结构化 timeline plan，CLI 执行并 lint，最后人工实开；任何直接改 JSON 的绕行都判失败。

后续机会：连续 3 个真实草稿一致后再进入批量字幕/B-roll；否则退回固定脚本。
