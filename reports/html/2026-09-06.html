#1 Resolve 自动剪辑审计包：一次 Agent 任务 → execution trace → Markdown/JSON 报告 → 人工只看异常与未验证项 · 99

核心判断：export_execution_report 把一次自动编辑的 request、status、timing、semantic deltas、verification、warnings 导出为独立报告，并修复“无验证证据却显示 Passed: yes”的危险语义。比继续增加编辑工具更有价值。

解决的问题：一次 Agent 剪辑包含多次调用后，很难快速判断真正改了什么、哪些步骤验过、哪些只是 API 没报错。

主流方案对比：聊天日志不可稳定验收；逐个 _operation 又太碎。execution report 把任务级结果收束成可留档材料，同时保留 unverified/partial/warning。

今天可以做：在测试项目跑一次 5–10 步真实编辑，导出 Markdown report，核对 semantic deltas、unverified 状态与最终时间线是否一致。

后续机会：连续 5 次报告与时间线一致后，把 report 固定为 Blueprint 后的自动执行验收件，只人工复查异常项。

#2 小红书执行闭环：决策证据 → action intent → execution receipt → 发布/改稿结果可追溯 · 98

核心判断：decision dataset query 与 action execution receipts 把“为什么做”“准备做什么”“实际执行结果”串起来，价值不在自动运营，而在可复盘。

解决的问题：建议、人工确认、真实执行和结果散落在聊天与页面里，一周后难区分判断错误还是执行失败。

主流方案对比：只留聊天记录最省事但不可审计；完整运营数据库过重。decision dataset + receipt 只保留关键事实，成本更低。

今天可以做：用 3 个真实动作验证：只研究、局部改稿、发布预览但不自动确认；检查每个 intent 是否有 receipt 且能区分成功、未执行和失败。

后续机会：若历史记录能直接回答“为什么做、做了什么、结果如何”，就把 receipt 作为周复盘唯一执行事实源。

#3 跨平台认知更新收件箱：推荐/反馈变化 → pending-list → 逐条查看 → 看过后再清队列 · 96

核心判断：OpenBiliClaw 新增 cognition update pending-list，并给历史更新生成稳定 id；系统对偏好的认知变化第一次可以完整回看，而不是只看最后一条通知。

解决的问题：跨平台研究运行一整天后，长期偏好已经变化，但用户可能漏看中间产生的认知更新。

主流方案对比：只弹最新通知容易漏；原始行为日志信息量过大。pending-list 保留的是已经提炼后的认知摘要。

今天可以做：跑一次小规模候选发现和显式反馈，再读取 pending-list，检查未读更新是否完整、seen 是否只清对应项目。

后续机会：连续一周无漏项后，把它作为每天一次的“偏好变化收件箱”，只人工纠正重要变化。

#4 剪映口播重拍粗剪：脚本/字幕约束 → detect-retakes → 只给删除候选 → OTIO 字幕往返 → 人工实开 · 94

核心判断：今天 capcut-cli 的新提交只是文档更新，因此不为了“有新提交”换方案。v0.22 的字幕约束重拍检测仍然更直接解决真人口播返工。

解决的问题：同一句录多遍需要人工逐段听，LLM 自由删句可能误删正确 take，跨 NLE 还可能丢字幕。

主流方案对比：静音检测识别不了重复语义；LLM 自由编辑不可控。字幕 cue 重拍检测更适合作为低风险候选层。

今天可以做：拿 3–5 分钟真实口播检查 10 个 retake 候选；至少 80% 正确后再做 OTIO 字幕往返和剪映实开。

后续机会：达到准确率门槛且不丢字幕，再接入口播初筛；否则保持提示候选，不自动删除。

#5 长视频拆条下载门禁：真实 YouTube probe → 免费静态线路优先 → 代理预算封顶 → 再进入 AI 高光检测 · 92

核心判断：OpenShorts 最近把真实 YouTube watch-page 探测、免费线路优先、付费代理每日预算 cap 和 cookie 复用放到取源层。对长视频拆条，先保证可靠取源和成本上限，比先优化高光模型更重要。

解决的问题：视频还没进入转录和高光检测，就因为反爬、代理误判和按流量重试造成失败或成本失控。

主流方案对比：yt-dlp 失败后无限换代理最简单但成本不可控；自建下载集群又过重。目标站 probe + 免费优先 + 预算 cap 更低成本。

今天可以做：只用 3 条公开视频测试免费、静态 fallback、付费 fallback 三层命中率和流量，先证明取源稳定，再跑高光检测。

后续机会：三条都能在明确预算内稳定取源后，再评估 AI moment detection；否则停止，不为高光模型继续投入。
