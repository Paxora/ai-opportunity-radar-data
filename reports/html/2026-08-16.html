#1 Resolve 画面级验收：自动修改 → timeline_frame 截帧 → 视觉核对 → 人工批准 · 99

核心判断：v2.96.0 新增 timeline_frame，MCP 可以直接返回 Resolve 当前最终合成画面，包含调色、Fusion、标题和转场，而不是只从时间线元数据推断结果。对自动剪辑最直接的价值是把验收从“结构正确”推进到“实际画面正确”。

解决的问题：解决自动写入后 API/时间线结构都显示成功，但字幕未渲染、Fusion异常、转场或调色实际画面不对时仍被误判为成功的问题。

主流方案对比：普通 Resolve 自动化主要回读 clip、marker、track、属性等结构信息；timeline_frame 直接让模型看到最终 composited frame，能覆盖元数据无法证明的视觉结果，同时 capture 后会恢复页面、播放头和当前时间线。

今天可以做：在一个测试时间线做3类改动：标题、变焦/Fusion、转场；每类改完分别截修改前后帧，让 AI 只回答“预期变化是否真正可见”，人工最后批准。暂时不让视觉判断直接驱动正式项目写入。

后续机会：如果连续10次修改都能用截帧发现可见失败，就把 timeline_frame 固定为每个高风险写操作后的验收门；如果检出率不高，只保留在标题/Fusion/调色等元数据难证明的动作。

#2 OpenBiliClaw：多源失效降级 → 免费搜索兜底 → 候选池不断供 → 人工选题 · 97

核心判断：8月15日的新提交把灵感检索后端变成 local_cache → platform_sources → Bing RSS → Exa → You，并修复来源份额已满但全局候选池仍欠量时的补货停滞。价值不是多一个搜索源，而是当微博/V2EX/YouTube等来源不可用或限流时，候选池还能用健康来源和无 Key 搜索继续供给。

解决的问题：解决热点研究链只要某个上游被限流、拒绝或外部搜索服务没配置，就出现候选数量不足、当天选题池断供的问题。

主流方案对比：单一爬虫或单一搜索 API 故障时通常整条链路变空；该方案把平台源、无 Key Bing RSS、Exa/You 直连和本地缓存做成分层降级，但最终创意选择仍应人工完成。

今天可以做：关闭 Exa/You Key，并人为让一个平台源失败，只跑20条候选；检查是否仍能补满、每条是否有可追溯来源。若补满但质量明显下降，就只把兜底结果标记为低优先级，不自动进入拍摄。

后续机会：如果一周内多次发生来源失败但候选池仍稳定，就把“来源可用性”和“证据质量”一起写进选题卡；如果平时很少断供，不再继续扩后端。

#3 Social Account Doctor：对标关键帧保留 → 同屏证据复盘 → 下一条拍摄改法 · 95

核心判断：最新修复保证详细报告中的 benchmark images 不会丢失。结合此前关键帧画廊能力，真正价值是把自己的视频与对标视频的画面证据留在同一份复盘里，避免报告只剩文字结论。

解决的问题：解决复盘时模型说“对标前3秒更强、人物更早出现、证明动作更清楚”，但报告里没有对应对标画面，导致结论无法快速核对的问题。

主流方案对比：传统数据面板只能看播放和互动，通用视频分析常把对标证据压成文本；保留 benchmark images 后可以直接做画面对画面的结构比较，但仍不应把评分当作最终选题决策。

今天可以做：拿1条自己视频+3条同类对标，只比较前3秒、人物出现、核心证明、CTA四个维度；每个判断必须旁边保留自己的关键帧和对标关键帧，没有画面证据的建议全部删除。

后续机会：连续复盘5条后，只留下能稳定对应完播率、互动或转化变化的2-3个画面维度，形成固定拍摄检查表。
